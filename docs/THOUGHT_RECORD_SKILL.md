# 개발 사고 기록과 회고 스킬 사용지침서

이 스킬은 AI와 함께 개발하면서 오간 대화와 프로젝트에서 확인한 근거를 바탕으로
개인 개발 기록을 만든다. 완성된 결과만 요약하지 않는다. 처음 무엇을 기대했는지,
어디서 생각이 어긋났는지, 무엇을 확인하며 판단을 바꿨는지, 새로 학습한 내용이
현재의 이해에 어떻게 연결됐는지를 남긴다.

기본 결과물은 자신의 Notion 하위 페이지에 생성되는 한 개의 문서다. 공개 기술
블로그나 포트폴리오를 만들기 위한 기능이 아니라, 미래의 내가 당시의 판단을 다시
이해하기 위한 기록이다.

## 어떤 자료를 사용하는가

기록은 두 종류의 근거를 함께 사용한다.

```text
현재 접근 가능한 AI 대화
  질문, 정정, 반박, 실패한 접근, 선택의 변화
              ↓
관련 프로젝트 근거
  코드, diff, commit, 오류, 명령 결과, 실행한 검증
              ↓
개인 사고 기록
  고민의 흐름, 학습한 것, 지금의 이해, 남은 질문
```

대화는 흐름을 복원하는 근거이고, 저장소는 그 흐름이 실제 결과와 맞는지 확인하는
근거다. AI가 제안했지만 구현하지 않은 내용은 결과처럼 기록하지 않는다. 확인할 수
없는 과거 대화나 실행하지 않은 테스트도 추측해서 채우지 않는다.

기본 대화 범위는 현재 접근 가능한 세션이다. 다른 세션을 함께 기록하려면 그
세션이 현재 환경에서 읽을 수 있어야 하고, 사용자가 포함할 범위를 지정해야 한다.

## 언제 사용하면 좋은가

작업 규모와 상관없이 다음과 같은 흔적을 남기고 싶을 때 사용한다.

- 처음 생각과 실제 관찰이 달랐던 작업
- AI와 대화하면서 요구사항이나 접근이 달라진 작업
- 실패한 시도가 다음 판단에 영향을 준 작업
- 구현보다 문제를 정의하는 데 시간이 걸린 작업
- 새로 알게 된 사실을 자신의 기준으로 정리하고 싶은 작업
- 해결하지 못했지만 지금까지 확인한 범위를 남기고 싶은 작업

조건을 일정 개수 이상 만족해야 하는 것은 아니다. 하나의 질문이라도 나중에 다시
보고 싶다면 회고형 기록을 사용한다. 고민의 변화가 거의 없었던 반복 작업은 변경과
검증만 담은 짧은 작업 기록으로 정리한다.

## 요청하는 방법

프로젝트에서 평소처럼 작업한 뒤 자연어로 요청하면 된다.

```text
이번 세션에서 내가 고민한 과정과 새로 이해한 내용을 Notion에 기록해줘.
```

```text
처음 가설이 왜 틀렸는지와 지금의 이해가 드러나게 회고로 남겨줘.
```

```text
아직 해결하지 못한 부분도 숨기지 말고 현재까지의 사고 기록을 만들어줘.
```

원하는 초점을 덧붙일 수도 있다.

```text
성능 수치보다 측정 방법을 의심하게 된 과정을 중심으로 기록해줘.
```

```text
구현 내용은 짧게 쓰고, 요구사항을 다시 정의한 과정을 자세히 남겨줘.
```

사용자가 제목이나 목차를 미리 정할 필요는 없다. 특정 사건을 반드시 포함하거나
제외해야 한다면 요청에 직접 적는다.

## 두 가지 게시 방식

### 요청 기록

커밋이나 push 계획과 무관하게 현재 작업을 기록하고 싶을 때 사용한다. 미커밋 작업,
조사만 한 세션, 코드가 바뀌지 않은 개념 질문도 기록할 수 있다.

이 방식은 Notion 문서를 생성하고 다시 읽어 확인하지만 `pnpm notion:mark`를
실행하지 않는다. push guard 상태에도 영향을 주지 않는다.

### Push 기록

최종 계획 commit을 만든 뒤 push 전에 사용하는 방식이다. 아직 upstream에 없는
commit 묶음과 그 작업 대화를 한 문서로 기록한다. 문서 생성과 재확인이 끝난 뒤에만
다음 명령으로 현재 commit과 연결한다.

```sh
pnpm notion:mark -- "<생성한 Notion 문서 URL>"
```

이 방식도 문서 생성 자체가 push 승인을 뜻하지 않는다. commit과 push는 각각
사용자의 명시적인 요청이 있어야 한다.

## 처음 한 번 필요한 설정

checkout마다 자신의 Notion 하위 페이지를 설정한다.

```sh
pnpm notion:setup -- "<내 Notion 하위 페이지 URL>"
pnpm notion:status
```

현재 Agent 세션에서 Notion MCP가 실제로 연결되어 있어야 한다. 설정 파일에 서버가
적혀 있다는 사실만으로 연결된 것으로 보지 않는다.

## 글은 어떻게 만들어지는가

스킬은 고정된 질문지를 채우지 않는다. 현재 작업에서 가장 중요한 흐름을 찾아 다음
내용을 줄글로 연결한다.

```text
처음의 질문이나 기대
→ 마주친 문제나 제약
→ 확인한 내용과 시도
→ 판단을 바꾼 근거
→ 최종 선택
→ 학습한 것
→ 지금의 이해와 남은 질문
```

회고 본문은 `~했다`, `~였다` 형태의 자연스러운 과거형을 기본으로 한다. 현재도
유효한 이해나 아직 남은 문제는 현재형으로 쓸 수 있다. 문장 끝을 억지로 모두 같은
형태로 맞추지는 않는다.

기록은 생각을 꾸며내지 않는다. AI의 내부 추론을 적는 것도 아니다. 대화에서 실제로
드러난 질문, 수정, 선택과 프로젝트에서 확인한 결과만 재구성한다.

## 학습한 것과 지금의 이해

`학습한 것`은 이번 작업에서 새로 확인한 사실, 제약, 기술, 진단 단서다. `지금의
이해`는 그 사실을 바탕으로 자신이 현재 세운 설명과 다음에 적용할 판단 기준이다.

예를 들어 `GPS 값이 전달됐다`는 관찰이고, `위치 오류를 보면 센서부터 의심하기보다
좌표계와 기준점을 함께 확인해야 한다`는 현재의 이해다. 아직 검증하지 못한 범위가
있다면 결론에 섞지 않고 남은 질문으로 둔다.

학습이 없었던 일상적인 작업에는 교훈을 억지로 만들지 않는다.

## Notion 문서 모양

페이지는 장식보다 읽는 흐름을 우선한다.

- 제목에는 실제 질문이나 판단 변화를 담는다.
- 본문은 한 열로 구성한다.
- 첫 화면에는 제목과 도입, 본문의 시작이 보이게 한다.
- cover, 장식용 아이콘, 이모지 소제목, 반복되는 색상 박스는 사용하지 않는다.
- callout은 현재 상태나 주의사항을 강조할 필요가 있을 때 하나만 사용한다.
- 명령어, 오류, 파일 목록, 검증 정보는 페이지 아래의 토글에 둔다.
- 별도의 하위 페이지는 기본적으로 만들지 않는다.
- 날짜는 제목에 기호로 붙이지 않고 속성이나 기록 정보에 둔다.

본문 아래에는 필요한 경우에만 다음 토글을 둔다.

```text
작업 근거
검증 상태
기록 정보
```

출처 목록을 관례적으로 추가하지 않는다. 실제 판단을 바꾼 자료가 있다면 관련 문장
또는 작업 근거 토글에서만 연결한다.

## 프로젝트 스킬과 개인 스킬의 차이

프로젝트에서는 `.agents/skills/project-notion-worklog`가 우선한다. 이 스킬은
현재 저장소의 Notion 대상, commit 범위, `notion:mark`, push guard 규칙을 알고
있다.

사용자 로컬의 개인 스킬은 다른 저장소에서도 같은 기록 방식을 사용할 수 있게 한다.
다만 프로젝트에 전용 기록 스킬이나 push 규칙이 있으면 프로젝트 규칙을 먼저 따른다.
개인 스킬이 임의로 commit, push, 외부 게시를 수행하지 않는다.

## 기록에 포함하지 않는 것

- 대화 전문과 AI의 내부 추론
- 실제로 고려하지 않은 선택지
- 실행하지 않은 명령이나 테스트
- 확인되지 않은 성능 개선과 결과
- 비밀번호, 토큰, 개인정보, 원본 사용자 데이터
- 모든 작업을 성공담으로 보이게 만드는 교훈

문서를 만든 뒤에는 Agent가 Notion 페이지를 다시 읽어 제목, 본문 흐름, commit 범위,
검증 상태, 토글 렌더링을 확인한다. 화면 확인이 불가능했다면 의미상 재확인만 했다는
사실을 결과에 남긴다.
